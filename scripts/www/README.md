# 地铁内涝风险评估（单站演示原型）

这是一个适用于 Windows 的轻量网页原型，采用单个 HTML 文件，无需安装开发环境或依赖包。

## 打开方式

1. 下载或解压项目文件。
2. 双击 `index.html`，用电脑上的浏览器打开。
3. 打开后默认进入**首页**：在上方搜索框输入站名，或点"定位推荐"让系统推荐最近车站；站点要素会自动填充。
4. 底部导航可切换三个页面：**首页**（评估信息 + 风险等级徽章）、**图表**（风险等级、趋势图、疏散示意）、**建模**（4D 水位演示视频）。建模页需要 `地铁内涝_4D水位演示.mp4` 与本页面在同一文件夹。

建议使用新版 Microsoft Edge 或 Google Chrome。天气服务和定位需要联网与浏览器授权；即使离线或拒绝定位，也可以搜索或手动填写参数使用系统。

## 功能

### 站点快捷选择

- **搜索车站**：支持站名或城市名模糊匹配（如输入"北京西站"或"成都"），点击或回车即可选中。内置全国主要城市的地铁站，本地即时搜索，无需联网。
- **联网搜索补充**：当内置站库没有匹配时，可点击"联网搜索"按钮，通过开放地名库在线查找（结果仅供参考，可能不准确，请核对）。
- **定位推荐**：点击"定位推荐"，浏览器会请求定位权限，并按距离推荐最近的 3 个站点，自动载入最近的一个。权限被拒绝、定位服务关闭或超时时，都会给出中文提示，并可直接改用搜索或手动填写。
- **自动填充**：选中站点，或在"车站名称"框输入站名后失焦 / 按回车，系统按"站型 × 城市规模"自动推荐埋深、出入口数量、客流等要素，并用浅蓝底色标记为估算值；手动修改后标记自动消失。站型依据站名特征（铁路/机场枢纽等）与真实换乘线路数判断；地质环境按城市地理特征估算。如需完全手动输入，点"恢复默认"。
- **我的站库**：填写好某站信息后点"保存为我的站点"，即可长期在搜索框调用；支持导出为 JSON 文件、再导入到其他电脑。

### 便捷操作

- 输入后自动评估（约 0.3 秒防抖），无需反复点击按钮。
- **演示情景一键套用**：首页顶部"极端暴雨 · 枢纽站""持续暴雨 · 普通站"，一键填入全部要素。
- **首次使用引导**：首页顶部三步引导卡（搜索车站 → 动态趋势 → 3D 建模），点"知道了"后 7 天内不再自动弹出。
- 天气情景快捷按钮：小雨 / 短时强降雨 / 持续暴雨，一键套用降雨参数。
- 自动记住上次填写的全部信息，下次打开自动恢复。
- 可选查询城市未来 6 小时逐小时降雨，并将峰值和有雨时长载入天气输入框；查询后仍可手动修改。
- 一键"打印 / 另存为 PDF 报告"，生成包含站点、输入、模型指标、疏散时间与免责说明的纸质报告。
- 展示可解释的模型结果：预估积水深度（环形仪表盘）、风险等级、水量平衡指标、积水演化曲线和简化车站示意图。

### 风险情景变化图（积水演化）

- 图表页"风险情景变化"图直接展示未来 6 小时的站台积水深度曲线（彩色线 + 各小时深度标注，点色随等级变化），并标注 0.15 / 0.30 / 0.50 米三级警戒参考线，修改参数即实时更新。

### 疏散示意与积水动画

- 疏散图按实际出入口数量（1–8 个）自动生成不同布局，每条出口线路显示分配客流人数、走行时间与清空时间。
- 客流分配采用**行人流模型**：出口通行能力 = 有效宽度 × 比流量（Fruin 参考值），步行速度随积水深度折减，按"等清空时间"原则最优分配；**绿色标记走行时间最短的最优路线**，并给出总疏散时间。
- 站台积水深度由水量平衡模型计算并带波浪动画，与降雨量、排水能力联动。
- 图表页末尾的**"计算实例（疏散模型代入验证）"**卡片会显示当前输入的公式代入过程，并列出 4 组对照案例；公式推导与逐步验算见下文「数学模型依据」与「图表实例：真实数据验证」。

### 天气背景与音效

- 背景随降雨量分五档变化：晴（无特效）/ 小雨 / 中雨（乌云与雨丝）/ 大雨 / 暴雨（乌云、密集雨、闪电）。
- 右上角"音效开关"（默认关闭，浏览器政策要求用户主动开启）：开启后合成雨声，大雨及以上档位伴随雷声。声音由浏览器实时合成，无外部音频文件。

### 建模页（4D 水位演示视频）

- 建模页播放参考演示视频《地铁内涝_4D水位演示.mp4》：通用双层地铁站剖视模型，积水由轨行区漫上站台，求生通道全程标识，镜头缓慢往返。
- 视频下方实时显示**演示时间、站台积水深度（两位小数，相对站台地面）、当前演示阶段**，水位按视频关键节点线性变化，四阶段为：初始状态 → 积水进入 → 持续上涨 → 终态展示。
- 请确保该视频文件与本页面在同一文件夹；无法播放时页面会显示提示。水位与阶段数据为演示示意参数，非实际测量值。

### 数学模型依据

#### 内涝严重程度——地表产流 + 水量平衡

1. **地表产流（推理公式）**：`Q_in = C · I · A · β / 1000`

   | 符号 | 含义 | 取值 |
   |---|---|---|
   | `C` | 径流系数（由土壤透水性决定） | 0.70 / 0.85 / 0.95 |
   | `I` | 降雨强度（毫米/小时） | 用户输入 |
   | `A` | 汇水面积（平方米） | 出入口数 × 3000 × 地势系数（0.8 / 1.0 / 1.5） |
   | `β` | 防汛设施挡水系数 | 1.0 / 0.85 / 0.70 |
   | 结果 | 进水量（立方米/小时） | — |

2. **排水抽排量**：`Q_out = Q_pump · η`，其中 `Q_pump` 由排水等级取基数（60 / 180 / 300 立方米/小时），`η = 1 / (1 + 0.015 · H)` 为埋深扬程折减系数（`H` 为车站埋深，米）。

3. **水量平衡求水深**：
   ```
   Q_net = Q_in − Q_out                    （净积水速率，立方米/小时）
   上涨速率 = Q_net / A_platform           （米/小时）
   h = min(3, max(0, 上涨速率 × T))        （预估积水深度，米；T 为降雨持续时间）
   ```
   其中 `A_platform = 1200 + 180 × 出入口数`（站台及轨行区有效蓄水面积，平方米）。

4. **风险分级**：按 `h` 与 0.15 / 0.30 / 0.50 米阈值分为低 / 中 / 高 / 很高四个等级。

#### 客流疏散——Fruin 行人流模型 + 等清空时间最优分配

所有公式与代码中的 `EVAC_MODEL` 常量一一对应。取行人自由步行速度 `v₀ = 1.2 m/s`（公开取值区间 1.20–1.40 m/s 的下限，偏保守）。

1. **积水对步行速度的折减**
   ```
   v(h) = v₀ · max(0.3, 1 − k · min(1, h / h_ref))
   ```
   | 符号 | 含义 | 取值 |
   |---|---|---|
   | `v₀` | 自由步行速度 | 1.2 m/s |
   | `k` | 折减系数 | 0.5 |
   | `h_ref` | 速度减半的参考水深 | 0.5 m |

2. **出口有效宽度**
   ```
   W_e = W − δ
   ```
   `W = 1.8 m`（出口通道宽度），`δ = 0.3 m`（两侧边界层各 0.15 m）→ `W_e = 1.5 m`。

3. **Fruin 比流量下的实际通行能力**
   ```
   C = q_s · W_e · 60 = 0.85 × 1.5 × 60 = 76.5 人/分钟
   ```
   `q_s = 0.85 人/(米·秒)` 为楼梯上行比流量（Fruin 参考值）。

4. **到各出口的走行距离与走行时间**
   ```
   L_i      = |x_i| + L_c + (r · H + L_e)
   t_walk,i = (|x_i| + L_c) / v(h) + (r · H + L_e) / v_s
   ```
   | 符号 | 含义 | 取值 |
   |---|---|---|
   | `x_i` | 第 i 个出口相对站台中心的水平距离 | 由出入口数量决定（最大 ±70 m） |
   | `L_c` | 站厅水平走行距离 | 15 m |
   | `r` | 楼梯坡道换算系数（约 30° 坡） | 1.7 |
   | `H` | 车站埋深 | 用户输入（米） |
   | `L_e` | 出口上行楼梯段长度 | 6 m |
   | `v_s` | 楼梯上行速度 | 0.6 m/s |

5. **等清空时间最优分配（water-filling）**——使各出口的清空时间趋于相同 `T*`，从而最短化总疏散时间：
   ```
   求 T* 使  Σ_i  max(0, C · (T* − t_walk,i / 60))  =  N
   分配人数   P_i = C · (T* − t_walk,i / 60)
   ```
   `N` 为站内客流总数。上式用二分法求解（40 次迭代）。

6. **总疏散时间与最优路线**
   ```
   T_total = t_r + 60 · T*        （秒；t_r = 60 s 为察觉险情与启动疏散的反应时间）
   i* = argmin_i t_walk,i         （走行时间最短者为最优疏散路线）
   ```

模型参数均为工程参考取值（可调），非实测标定值，详见页面内的"模型说明"与结果卡片。

### 图表实例：真实数据验证

下表用于核对公式的**计算过程**，并代入真实站点作对照。表中"真实数据"指：站名与换乘线路数（取自 Wikidata 公开数据）、车站类型（铁路枢纽 / 换乘站，按站名与线路数判定）。**埋深、出入口数量、站内客流为系统估算值**（公开数据库无全国分站实测数据），降雨情景为设定值。所有数值均由页面中的模型实时计算得出，可直接与「图表」页的"计算实例"卡片对照。

**计算前提（所有实例相同）**：`W_e = 1.5 m`，`C = 76.5 人/分钟`，`L_c = 15 m`，`r = 1.7`，`L_e = 6 m`，`v_s = 0.6 m/s`，`t_r = 60 s`。

|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 普通站 · 小雨 | 普通站（0 换乘） | 10 m | 2 | 1,000 人 | 0.00 m | 低 | 1.20 m/s | 出口 1 | 78.7 / 78.7 | 7.85 分 | 8.8 分（531 秒） |
| 2 | 普通站 · 中雨 | 普通站（0 换乘） | 10 m | 2 | 1,000 人 | 0.15 m | 中 | 1.015 m/s | 出口 1 | 86.0 / 86.0 | 7.97 分 | 9.0 分（538 秒） |
| 3 | 体育西路站（广州）· 强降雨 | 1/3/3北 三线换乘 | 15 m | 6 | 3,000 人 | 1.67 m | 很高 | 0.60 m/s | 出口 3 | 174.5 / 135.1 / 95.7 / 98.7 / 138.1 / 177.5 | 8.81 分 | 9.8 分（589 秒） |
| 4 | 北京西站 · 极端暴雨 | 铁路枢纽 + 7/9 两线换乘 | 19 m | 7 | 3,600 人 | 3.00 m | 很高 | 0.60 m/s | 出口 4 | 188.6 / 154.8 / 121.1 / 90.4 / 124.1 / 157.9 / 191.7 | 9.17 分 | 10.2 分（610 秒） |

> 读懂第 3、4 行：站点越大（出入口越多、换乘线路越多），站内客流越大，但每个出口的通行能力不变（均为 76.5 人/分钟），因此**总疏散时间主要由客流与积水深度决定，而不是出口数量**——出口多只是让人流分配更均衡。两站最终总疏散时间接近（9.8 分 vs 10.2 分）正说明这一点。


**实例 2 的逐步验算**（可自行核对）：

```
已知：H = 10 m，出入口 2 个，v₀ = 1.2 m/s，N = 1000 人
      水量平衡模型给出 h = 0.1544 m（界面按 2 位小数显示为 0.15 m）

① v(h) = 1.2 × max(0.3, 1 − 0.5 × min(1, 0.1544 / 0.5))
        = 1.2 × (1 − 0.5 × 0.3088) = 1.2 × 0.8456 = 1.015 m/s

② 楼梯段长度 = r·H + L_e = 1.7 × 10 + 6 = 23 m
   → 楼梯走行时间 = 23 / 0.6 = 38.3 秒

③ 出口 1 相对站台中心的水平距离
   |x₁| = |230 − 376| × (2 × 70 / 612) = 146 × 0.2288 = 33.4 m
   （像素坐标换算为米：站台全长 140 m 对应图中 612 像素）

④ t_walk,1 = (33.4 + 15) / 1.015 + 38.3 = 47.7 + 38.3 = 86.0 秒
   （出口 2 对称，同为 86.0 秒）

⑤ 等清空时间：解 2 × 76.5 × (T* − 86.03 / 60) = 1000
   → T* = 6.536 + 1.434 = 7.97 分钟
   分配人数 P₁ = P₂ = 76.5 × (7.97 − 1.434) = 500 人

⑥ T_total = 60 + 60 × 7.97 = 538 秒 ≈ 9.0 分钟
```

> 关于取整：界面与本节表格按 2 位小数显示，页面"计算实例"卡片中 v(h) 按 3 位小数、走行时间按 1 位小数显示，因此会出现 1.015 与 1.02 之类的细微差别，二者是同一个值的不同舍入结果。

**积水深度敏感性分析**（枢纽站，7 出入口，埋深 19 m，3,600 人）：

| 积水深度 h | 步行速度 v(h) | 与自由速度之比 | 总疏散时间 T_total |
|---|---|---|---|
| 0.00 m | 1.200 m/s | 100% | 9.5 分 |
| 0.15 m | 1.020 m/s | 85% | 9.6 分 |
| 0.30 m | 0.840 m/s | 70% | 9.8 分 |
| 0.50 m | 0.600 m/s | 50% | 10.2 分 |
| ≥ 0.50 m | 0.600 m/s（下限 0.3·v₀） | 50% | 10.2 分 |

**通行能力量级核对**：模型取 `q_s = 0.85 人/(米·秒)`，即每米有效宽度约 51 人/分钟。公开的 Fruin 行人流研究中，楼梯上行比流量的常见取值区间约为 0.6–1.3 人/(米·秒)，本模型取值位于区间内偏保守一侧；1.5 m 有效宽对应的通行能力 76.5 人/分钟，与地铁车站出口通行能力的常见量级一致。这说明模型输出的**量级**是合理的，但具体数值仍受站点几何、泵组能力与客流分布影响，不能替代实测。

## 重要使用边界

本原型面向学习、演示和方案展示。上述数学模型为简化工程估算，参数未按具体站点实测标定，阈值是参考取值而非行业标准。趋势图是假设当前降雨条件持续的情景推演，并非天气预报或精确水动力预测。客流疏散图没有使用真实车站图纸、实测泵组能力或实时客流。请勿将结果用于实际运营决策、预警发布或应急指挥。

**关于站点数据**：内置站库覆盖全国开通轨道交通的主要城市（约 60 个城市、6700 余个车站），由开放数据 Wikidata 生成，站名为简体中文。坐标是公开数据的近似值（误差可能达数百米），仅用于"距离最近"推荐。**换乘线路数是 Wikidata 的真实数据**，用于区分普通站、两线/三线换乘站；而**埋深、出入口数量、客流、地质环境是演示估算值**——公开数据库不存在全国分站的真实数据（已多源核验），系统按站型与城市规模用规则推算并在界面标注"请核对"，请务必按实际情况核对后再使用。站库随页面内置，本地搜索不需要联网；联网搜索使用 OpenStreetMap 地名服务（Nominatim）作为补充，其结果同样仅供参考。

天气数据来自 Open-Meteo 公共地理编码和天气预报服务，仅作参考。城市级预报无法代表具体车站的局地天气。定位由浏览器和 Windows 位置服务提供，精度取决于设备与环境。具体服务可用性取决于网络和服务提供方。

所有数据只保存在您自己的电脑浏览器本地（localStorage），不会上传到任何服务器；清除浏览器数据会一并清除“我的站库”。
